## Что уже проверено

Получены 399 ответов A и 361 ответ B: 666 уникальных пар, 94 общие.
Независимость человеческих оценок и применимость обновлённой инструкции к
неизменившимся карточкам подтверждены участниками 15 ноября 2026 года.
Исходные файлы с `independent=false` сохранены побайтно; подтверждённые копии
меняют только этот флаг. Хеш пакета не менялся.

Каппа Коэна на числовых общих парах — 1,0; расхождений нет. 24 ответа имеют
статус `unjudgeable`, который не заменяется нулевой релевантностью.
[Исходники и проверка](../reports/b06/historical-652a8151/README.md).
Это оценка прежней TF-IDF-выдачи, а не принятой dense-модели.

Для текущего эксперимента перенесены 472 оценки при точном совпадении видимого
профиля, истории и публичной карточки. Начальные выдачи и 23 фиксированных
варианта весов требуют ещё 290 уникальных пар. Из них 203 недостающие пары
нужны для tune; до их получения победитель не выбирается, файл выбранных
весов не создаётся. Holdout не участвует в выборе.

## Что делают участники

1. Открыть [форму дополнения](../artifacts/weight_tuning/form.html) в браузере.
   Она содержит только недостающие пары. Повторять уже принятые ответы не нужно.
2. Каждый выбирает прежний код A или B, независимо заполняет назначенные
   карточки, подтверждает самостоятельность и скачивает JSON.
3. Передать оба файла координатору. Общие ответы до скачивания не обсуждать.
4. Если появились расхождения, обсудить их после сохранения исходников.
   Решение записать отдельно, без редактирования ответов.

## Воспроизведение

CPU-окружение: `requirements-retrieval.txt` и `requirements-encoder.txt`,
локальные веса выбранной E5-small. При необходимости `MODEL_PATH` указывает
проверенную папку модели. Сеть во время оценки не нужна.

```sh
python -m alfarec.eval.tune_weights prepare --source-pool reports/b06/historical-652a8151/pool.json --source-answers reports/b06/historical-652a8151/confirmed-A.json reports/b06/historical-652a8151/confirmed-B.json --accept-instruction-update
python -m alfarec.eval.tune_weights select --answers supplement-A.json supplement-B.json
python -m alfarec.eval --handoff data/handoff
```

Ключ `--accept-instruction-update` фиксирует уже полученное подтверждение
применимости уточнённой инструкции; без него перенос между разными версиями
инструкции отклоняется. Исходный пакет всегда проверяется по собственному хешу.

`select` возвращает 2 при нехватке оценок, 1 при неверных входах, 0 только при
полном завершении. Файлы в `artifacts/weight_tuning/`: `experiment.json` —
фиксированные кандидаты и списки; `pool.json` — полный набор; `supplement.json`
и `form.html` — дополнение; `selection.json` — состояние выбора.

После выбора на tune могут появиться новые holdout-карточки, которых ещё не
оценивали. Тогда создаются `holdout_supplement.json` и `holdout_form.html`.
Участники заполняют их так же, а координатор повторяет ту же команду с
`--holdout-answers holdout-A.json holdout-B.json`. Настройки по holdout не меняют.

Для разбора расхождений `--resolutions` и `--holdout-resolutions` принимают JSON
с `pool_sha256` соответствующей формы и `answers`: объекты `profile_id`,
`item_id`, `grade` (0/1/2 или null), непустое обоснование `note`. Каждая
расходящаяся пара должна иметь ровно одно решение; исходная каппа сохраняется.

Только завершённый выбор сохраняет `artifacts/weights.json`, итоговые оценки,
списки и хеши доказательств. Его автоматически читает API B05 после перезапуска.
Текущее отсутствие выбранных весов честно оставляет B05 в review, B06 —
in_progress. Дополнительные человеческие оценки остаются обязательным входом.
