# B03: пять реальных калибровочных пар

Статус: **ожидаются две независимые человеческие оценки**. Пакет и форма подготовлены; результаты не заполнены. Это калибровка [инструкции](labeling.md), не сравнение рекомендателей и не часть holdout. [Спецификация](specs/b03-calibration.md).

## Действия участников

1. Координатор передаёт обоим один и тот же файл [`artifacts/calibration/form.html`](../artifacts/calibration/form.html). Он самодостаточный: открыть в обычном браузере двойным щелчком, сервер и сеть не нужны. Отображение на широком и узком окне, фокус с клавиатуры и скачивание JSON проверены в Edge; [протокол](../reports/calibration_ui.md). Не размещать файл на публичном хостинге: это производные данные кейса, предназначенные для команды и жюри.
2. Договориться о кодах A и B. Каждый отдельно читает шкалу и пять синтетических учебных примеров, оценивает пять реальных пар и пишет пояснения. До скачивания собственных ответов не смотреть оценки коллеги. Не додумывать требования из легенд: форма показывает только наблюдаемый профиль.
3. Написать замечание к инструкции (или явно указать, что замечаний нет), подтвердить самостоятельность и нажать «Скачать мои оценки · JSON». Передать координатору `b03-calibration-A.json` и `b03-calibration-B.json`. Имена и контакты не нужны. Ответы не сохраняются между открытиями; перед обновлением страницы скачать файл.
4. Координатор проверяет файлы и составляет отчёт командой ниже. Сохранить исходные ответы без редактирования в `reports/calibration/` отдельным коммитом после получения; сейчас этой папки с результатами нет. Вымышленные ответы из тестов не являются человеческой разметкой.
5. Участники обсуждают расхождения и все случаи `unjudgeable`. В отчёте указать итог каждой пары, основание, дату, коды участников и решение по инструкции: конкретное уточнение либо обоснование, почему оно не требуется. Сохранить исходные оценки до обсуждения. Совпадение пяти ответов само по себе не закрывает проверку понятности инструкции.
6. Добавить в [B03](tasks/CORE.md) ссылку на результаты и доказательства. До ручного разбора статус остаётся `review`; после полной приёмки и слияния соответствующего PR можно поставить `done`.

Координация — `prolgrammer`, оценки — два участника команды. Достаточно текущего каталога B02, оригинальный дамп не нужен. На других ветках каталог меняется: пакет фиксирует именно использованную версию. Нельзя переносить оценки на изменённые карточки автоматически.

## Пакет и версии

[`calibration_pairs.json`](../alfarec/eval/calibration_pairs.json) задаёт пять ID профилей и материалов. [`packet.json`](../artifacts/calibration/packet.json) содержит наблюдаемые профили, краткие карточки и SHA-256 входов: каталога, профилей, таксономии, инструкции, списка пар и всего шаблона формы с фактически показанной шкалой. Хеш текстовых файлов вычисляется после приведения переводов строк к LF, чтобы Windows и Linux давали один результат. Итоговый хеш пакета записан в форму и каждый ответ.

Профили P06, P18, P09, P03, P15 относятся к `tune`, без неразрешённых селекторов истории. Материалы выбраны вручную из публичного каталога B02: пять разных профилей и пять разных материалов, разные темы, форматы, длительности и виды доступа. Ожидаемых оценок нет. Отбор намеренный, поэтому результаты нельзя выдавать за репрезентативную оценку качества рекомендаций.

В форму не попадают `legend`, `expected_behavior`, источник алгоритма, позиция, score, популярность, внутренние метки или тексты уроков. URL исключён: калибровка относится к зафиксированной публичной карточке, а не к изменяющемуся содержимому страницы. `unjudgeable` хранится отдельным статусом, не нулём.

## Воспроизведение и проверка

Из корня репозитория в окружении с зависимостями проекта:

```sh
python -m alfarec.eval.calibration build --check
```

Команда без записи проверяет, что пакет и форма соответствуют текущим входам. При изменении каталога, профилей, таксономии, инструкции или списка пар она завершится ошибкой. Для осознанной подготовки **новой** калибровки:

```sh
python -m alfarec.eval.calibration build
```

После новой сборки нужны новые независимые ответы, даже если ID не изменились. Старый пакет, форму и ответы сохранять вместе в истории Git; отчёт ссылается на исходный хеш. Для простоты и надёжности хешируется весь шаблон, поэтому даже изменение одной лишь вёрстки создаёт новый пакет. Во время сбора ответов шаблон не менять.

После получения двух файлов (каталог назначения должен существовать):

```sh
python -m alfarec.eval.calibration compare reports/calibration/b03-calibration-A.json reports/calibration/b03-calibration-B.json --output reports/calibration/review.md
```

Проверяются хеш пакета, соответствие текущим источникам, разные коды участников, подтверждение самостоятельности, ровно пять неповторяющихся пар, допустимые оценки и непустые пояснения. Повторные ключи JSON, нечисловые константы, числовые строки, дроби, булевы значения вместо чисел и неизвестные поля отклоняются; версия должна быть целым числом `1`. Подтверждение самостоятельности — заявление участника, а не техническое доказательство личности; код A/B не позволяет программе установить, кто заполнял файл.

Отчёт содержит оба исходных ответа, число совпадений статусов и `unjudgeable` у каждого участника, заметки к инструкции и места для ручного итога. Kappa на пяти пробных парах не рассчитывается. Существующий отчёт не перезаписывается, чтобы сохранить обсуждение. Автоматического изменения статуса задачи нет.
