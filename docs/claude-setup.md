# Настройка Claude Code нового участника

Командная часть — правила, отключённая атрибуция, hooks и CI — приходит вместе с клоном. Настроить нужно то, что живёт на вашей машине: плагины, навыки, личные инструкции Claude, Git-личность и защиту `main` в клоне.

Что нужно заранее: аккаунт GitHub, добавленный владельцем в collaborators репозитория, установленный Claude Code и архив `claude-skills.zip` с навыками `team-git-cycle` и `verified-research` от владельца репозитория. Откройте Claude Code в папке, где будет лежать клон (или уже в клоне), и вставьте промпт ниже целиком.

## Промпт

```text
Привет. Настрой моё окружение Claude Code для командной разработки на хакатоне в репозитории https://github.com/ib1te1/alfa-hack-and-change. Процесс описан в самом репозитории; твоя задача — подготовить мою машину и мой клон, чтобы я работал по тем же правилам. Общайся по-русски. Я впервые использую Claude для такой разработки: кратко объясняй, что и зачем делаешь.

Общие правила на время настройки: не печатай и не сохраняй токены, пароли и содержимое credential-хранилищ; не меняй глобальный git config; не ставь и не авторизуй gh — удалённые операции идут через Git Credential Manager; ничего не пушь; существующие ~/.claude/CLAUDE.md и ~/.claude/settings.json дополняй, а не перезаписывай, и перед изменением показывай diff.

1. Диагностика. Определи ОС и проверь наличие и версии: Claude Code, git, Git Credential Manager, PowerShell 7 (pwsh), Python, uv, Node.js. Покажи таблицу «есть / нет / версия». Для недостающего предложи команду установки под мою ОС и жди моего «да». Обязательны git, GCM и pwsh; остальное — по стеку проекта.

2. Плагины. Нужны из маркетплейса claude-plugins-official: superpowers, code-review, frontend-design, context7, skill-creator, security-guidance. Проверь, какие уже стоят; недостающие попробуй поставить через `claude plugin install <имя>@claude-plugins-official`. Если CLI так не умеет — дай мне список команд `/plugin install ...`, я введу сам. Скажи, что после установки нужен перезапуск, а context7 авторизуется через /mcp.

2a. Навыки команды. Спроси, где лежит архив claude-skills.zip, который мне передал владелец репозитория. Распакуй его во временную папку и покажи мне name и description из каждого SKILL.md. После моего «да» скопируй папки team-git-cycle и verified-research в ~/.claude/skills/. Если папка с таким именем там уже есть — не перезаписывай, покажи разницу и спроси.

3. Глобальный ~/.claude/CLAUDE.md. Добавь разделы:
- Independent judgment: ты коллега со своим мнением, а не услужливый ассистент. На моё мнение, план или техническое решение сначала сформируй свой взгляд; при несогласии скажи прямо и аргументируй; меняй позицию от нового аргумента или факта, а не от того, что я повторил громче. Касается суждений и архитектуры, не рутинных просьб.
- Risky actions: всегда спрашивай перед публикацией пакетов; если задача тянет к действию за пределами просьбы — остановись и спроси.
- Completion criteria: закончив существенную задачу, сам запусти существующие typecheck/lint/test/build; при падении — несколько разумных попыток исправить, потом остановись и доложи. Для мелких правок не нужно.
- Environment: моя ОС и shell по итогам шага 1; для новых Node-проектов без lockfile — pnpm, в существующих — менеджер по lockfile.
- Token budget: спроси мой тариф (Pro / Max 5x / Max 20x / API). Для Pro добавь: код пишется один раз — прототип автора плана коммитится, а не переписывается исполнителями; реализация делится на подзадачи по границам затронутых файлов, каждой — свежий исполнитель со своим куском плана; одно финальное ревью ветки вместо ревью после каждой подзадачи, кроме рискованных мест; Opus — план и финальное ревью, Sonnet — исполнители и исправления; координатор не перечитывает файлы, о которых отчитался субагент; перед дорогим шагом проверяй расход и при занятости 5-часового окна больше 70% спрашивай меня. Для Max предложи смягчённую версию.

4. Клон и Git.
- Если репозиторий не склонирован — спроси, куда, и склонируй. Вход через GCM выполню я сам в браузере. Нет доступа — остановись: владелец ещё не добавил меня в collaborators.
- Выполни подготовку клона по docs/development.md: спроси мой логин GitHub, задай локальные user.name и user.email (noreply с ID), запусти scripts/setup-hooks.ps1 и проверь core.hooksPath.
- Если в репозитории уже есть зависимости проекта (pyproject.toml / uv.lock / package.json), установи их по lockfile.

5. Проверка.
- Запусти scripts/check.ps1 и scripts/test-checks.ps1, покажи результат.
- Попроси меня перезапустить Claude Code в папке клона и убедись, что видны навыки team-git-cycle и superpowers:brainstorming.

6. Ликбез. Прочитай AGENTS.md, docs/development-rules.md и docs/hackathon/WORKFLOW.md и объясни мне в 10–15 строках: где брать задачу и как её закрепить; одна задача = одна ветка = один PR; цикл нетривиальной задачи (brainstorming → спека в docs/specs → план в .work/plans → реализация → ревью); как продолжить после перерыва («где мы остановились», .work/STATE.md); когда можно merge; что запрещено.

В конце выведи итог тремя частями: что настроено и проверено; что я должен сделать руками; что не удалось.
```

## После настройки

Работайте обычными фразами: «возьми задачу B03», «где мы остановились», «открой PR», «можно мерджить?». Claude сам подхватит `team-git-cycle` и правила репозитория. Память Claude у каждого своя: всё, что важно команде, записывайте в документы репозитория.
