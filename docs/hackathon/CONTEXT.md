# Контекст кейса

Хакатон Changellenge Hack&Change 2026, кейс Альфа-Банка «Альфа-Курс: знания в нужный момент». Команда выбрала **трек 1 — персональные рекомендации образовательных материалов**. Трек 2 (ИИ-помощник в Telegram) не делаем: баллов за его функции не дают.

Исходные материалы получены от организаторов: PDF кейса, описание данных, описание структуры базы и дамп PostgreSQL `alfa_course_hackathon.backup`. Дамп и его копии в репозиторий не попадают (ограничение 01 кейса), см. [сводку по данным](DATA.md).

## Задача трека 1

Создать рекомендательную систему, которая подбирает пользователю материалы «Альфа-Курса» и объясняет выбор:

1. Изучить каталог и определить поля, которые помогают подобрать материал под задачу пользователя.
2. Реализовать подбор и ранжирование по профилю: стадия бизнеса, сфера, текущая задача, опыт и история просмотров, если она есть.
3. Предусмотреть холодный старт: полезная подборка для нового пользователя и короткий необязательный онбординг.
4. Объяснять каждую рекомендацию и предлагать следующий шаг.
5. Сравнить решение с простым бейзлайном (например, подборка по совпадению темы) на самостоятельно составленных тестовых профилях.
6. Предложить, как проверить влияние рекомендаций на конверсию после внедрения.

Бизнес-цель — рост средней конверсии в покупку образовательных продуктов; продуктовая — рост числа дней, в которые пользователь заходит на платформу. Решение должно оставаться полезным при недостатке сведений о человеке: пользователь может не знать терминов и не хотеть заполнять анкету.

Целевая аудитория из кейса:

| Пользователь | Ситуация | Какая помощь нужна |
|---|---|---|
| Начинающий предприниматель | Планирует открыть дело и не знает, с чего начать | Вводный материал и последовательность действий |
| Владелец малого или микробизнеса | Решает конкретную задачу по учёту, маркетингу или продажам | Краткая инструкция, готовый инструмент, ответ на точечный вопрос |
| Соло-фаундер, развивающий бизнес | Хочет системно разобраться в новой области | Подборка по уровню и объяснение, когда нужен углублённый курс |

Проверочные сценарии трека 1 (приложение 2 кейса):

- Новый пользователь обозначает задачу (например, продвижение бизнеса) — система выдаёт стартовую подборку и объясняет её порядок.
- Есть история действий — система учитывает журнал взаимодействий. Допустимы синтетические события.
- Холодный старт без журнала — рекомендации, повышающие частоту взаимодействия с платформой.
- Мало сведений или нет точного совпадения — уместное уточнение, более общая подборка или маршрут изучения.

## Формат сдачи

PDF-презентация со ссылкой на репозиторий на первом слайде либо ZIP-архив с кодом, документацией и PDF. Для приватного репозитория — доступ аккаунту жюри `hack-and-change-2026`. На первом слайде — порядок проверки, ссылка на репозиторий и, если есть, на развёрнутый интерфейс. Далее: проблема и пользователь, архитектура, сценарий, примеры работы, ограничения, идеи развития.

Состав репозитория: исходный код; `README.md` (назначение, архитектура, одна команда запуска через Docker, переменные окружения, порты, зависимости, входные данные, пошаговый сценарий проверки, известные ограничения, внешние API с моделью и переменной ключа); `Dockerfile`, `compose.yaml`, `.dockerignore`; файл зависимостей с зафиксированными версиями; `env.example` без рабочих ключей.

## Ограничения кейса

1. Данные — только для задания; не публиковать выгрузки и копии в открытом доступе и не передавать третьим лицам.
2. Сложные интеграции с банковскими и государственными сервисами не нужны.
3. Интерфейс простой и интуитивно понятный.
4. Без навязчивых уведомлений; поп-апы только оправданные.
5. Платные материалы: не раскрывать подробное содержание; кратко объяснить пользу и дать переход на страницу материала или покупки, только по предоставленным ссылкам.
6. Во внешние API — только необходимые фрагменты без персональных данных и закрытых материалов; для демонстрации — тестовые профили.

| Онлайн-этап | Вес | Финал | Вес |

| Качество рекомендаций | 25% | Качество живой демонстрации | 25% |
| Архитектура и документация | 20% | Ценность для пользователя и бизнеса | 20% |
| Персонализация и работа с неполными данными | 15% | План проверки эффекта и внедрения | 15% |
| Объяснимость и следующий шаг | 5% | Качество защиты и ответы на вопросы | 10% |
| Качество презентации | 5% | Командное владение решением | 5% |

Итог: онлайн-этап и финал по 50%. Шкала каждого критерия 0–5.
