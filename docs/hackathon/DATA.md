# Сводка по данным

Дамп `alfa_course_hackathon.backup` (custom-формат pg_dump, база `courses_for_bu`, 62 таблицы, 102 128 строк). Здесь только агрегаты и выводы для проектирования; сами данные в репозиторий не попадают. Подробная схема — в описании структуры базы от организаторов.

Дамп читается напрямую из Python библиотекой `pgdumplib` — PostgreSQL для работы решения не нужен. Это проверено: все 62 секции данных прочитаны, суммарное число строк совпало с описанием.

## Разметка для подбора

Разметка хранится в `ContentSettings` (полиморфная ссылка на статьи, курсы, документы, вебинары, подкасты) и связях с `Topics`, `Tags`, `Industries`.

| Поле | Покрытие | Качество |
|---|---|---|
| Темы `Topics` | 1148 из 1166 материалов, 1–3 темы | Пригодно. Лидируют «Налоги и законы» (566), «Финансы и учёт» (286), «Управление командой» (208). Есть дубли с латинскими буквами («Маркeтплейсы», «Прoдажи») и удалённые темы |
| Теги `Tags` — по смыслу «задача пользователя» | 1095 материалов | Слабо: 3 широких тега («Налоги и законы» 530, «Развитие бизнеса» 367, «Старт бизнеса» 162) покрывают ~97%; детальные теги («Выбор налогового режима», «Продвижение в соцсетях») почти не проставлены |
| Отрасли `Industries` — сфера и опыт | 207 материалов (160 статей, 36 курсов) | Смешаны сфера (ECom, Розница, Услуги, HoReCa, B2B…), опыт («Без опыта», «С опытом») и витринные метки («Актуальное», «NEW») |
| Рубрика статьи `ArticleSubjects` | 855 статей | Пригодно: ИП, ООО, Самозанятость, Маркетплейсы, Налоги и т. д. |
| Длительность `Duration` | Почти у всех | Строка «7 минут», «2,5 часа», «~2 часа» — нужен разбор |

Вывод: стадия бизнеса, детальная задача и уровень у большинства материалов **не размечены**. Их нужно восстанавливать из текста — это основная ML-часть решения.

Ограничения журнала:

- Просмотров статей, документов, глоссария нет совсем. История есть только по курсам, урокам и оценкам.
- У 79% пользователей ровно один курс; у 1562 пользователей два курса и больше — на них можно проверить предсказание следующего курса.
- Профиля пользователя (стадия, сфера, опыт) в данных нет. Тестовые профили составляем сами, как разрешает кейс.
- Покупки практически отсутствуют, поэтому влияние на конверсию офлайн не измерить — только план A/B-теста.

## Разметка релевантности, которую дала платформа

`RecommendedItems` — 3996 строк, 1336 редакторских подборок «смотрите также»: исходный материал (статья, документ, курс, глоссарий, вебинар, подкаст) → в среднем 3 связанных материала. `DocumentBindings` — 443 связи «документ → связанный документ».

Это независимая от нас разметка «что релевантно к чему». Используем её для объективной офлайн-проверки текстовой близости и выбора модели эмбеддингов, а не как сигнал на входе ранжирования (иначе проверка станет утечкой).

## Качество данных

- Кириллические названия с латинскими буквами-двойниками («Маркeтплейсы», «целeй»): нормализовать при сопоставлении.
- Удалённые (`IsDeleted`) и черновые записи справочников — исключать.
- HTML в описаниях: очищать до текста.
- Представление `vw_SubscriptionCatalog` для курсов опирается на тип сущности, которого нет в `ContentSettings`; курсы связываем с разметкой напрямую по `Courses.Id`.
