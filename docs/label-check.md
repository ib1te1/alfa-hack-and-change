# B04: ручная проверка разметки на 120 материалах

Статус: **выборка и форма готовы, ожидаются ручные метки**. По [ТЗ, раздел 6.1](specs/2026-11-13-recommender-tz.md) второй участник вслепую размечает 120 материалов (стадии, уровень, задачи), а точность и macro-F1 ML-разметки B04 считаются по каждому полю и источнику метки. Худший источник на поле не используется.

## Действия

1. Разметчик открывает в браузере [`artifacts/label_check/form.html`](../artifacts/label_check/form.html) — самодостаточный файл без сервера и сети. В форме только публичная карточка: название, описание, тип, формат, длительность, доступ. Модельных меток нет.
2. Для каждого материала отмечает стадии (можно несколько или ни одной), уровень или «не определить», от нуля до трёх главных задач. Ответы сохраняются в браузере; итог — кнопка «Скачать метки · JSON» (`b04-label-check.json`).
3. Подсчёт:

```sh
python -m alfarec.eval.label_check score b04-label-check.json
```

Если `artifacts/item_labels.parquet` (B04) уже есть, сравниваются его метки по `label_source`; иначе — текущие метки ранжирования по исходной разметке, чтобы получить точку отсчёта до B04. Результат — `reports/label_check.md`.

## Выборка и метрики

`python -m alfarec.eval.label_check sample` берёт 120 материалов с фиксированным зерном, пропорционально типам, но не меньше трёх каждого типа: 60 статей, 28 терминов глоссария, 20 документов, по 3 курса, вебинара, подкаста и калькулятора. Выборка фиксирует SHA-256 каталога; `--check` проверяет, что она соответствует текущему каталогу.

- Уровень — точное совпадение; материалы с ручным «не определить» не учитываются.
- Стадии и задачи — пересечение множеств; если оба пусты, это совпадение.
- Macro-F1 — среднее F1 по меткам «одна против остальных»; метки, которых нет ни у человека, ни у модели, пропускаются.
