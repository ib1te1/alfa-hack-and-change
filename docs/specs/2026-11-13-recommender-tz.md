# Техническое задание: персональные рекомендации «Альфа-Курса»

Версия 1.0 от 13 ноября 2026 года. Трек 1 кейса Альфа-Банка. Статус: рабочая спецификация; реализация ведётся по карточкам задач.

Связанные документы: [контекст кейса](../hackathon/CONTEXT.md), [сводка по данным](../hackathon/DATA.md), [матрица требований](../hackathon/REQUIREMENTS.md), [карточки ядра](../tasks/CORE.md), [улучшения](../tasks/IMPROVEMENTS.md).

## 1. Что делаем

**Польза одним предложением:** предприниматель за минуту и без анкеты получает короткий маршрут из материалов «Альфа-Курса» под свою задачу, стадию и опыт — с объяснением, почему каждый материал ему подходит и что сделать дальше.

Продукт — веб-сервис с REST API и одной страницей интерфейса, который запускается одной командой `docker compose up --build` и открывается на `http://localhost:8000`. Внутри — гибридная рекомендательная система: текстовые эмбеддинги + восстановленная ML-разметка материалов (стадия, уровень, задача, сфера) + интерпретируемое ранжирование + учёт истории + переранжирование на разнообразие и маршрут.

Чем выделяемся (то, что увидит жюри):

1. **Маршрут, а не лента.** Ответ на задачу — 3–5 шагов «разобраться → сделать → углубиться» с объяснением порядка: короткий ответ или термин, затем шаблон или калькулятор, затем курс. Это прямо закрывает сценарий «объясняет её порядок» и разницу пользователей из кейса (кому ответ, кому шаблон, кому курс).
2. **Разметка, которой нет в данных.** Стадия бизнеса, уровень и детальная задача почти не размечены (см. [DATA.md](../hackathon/DATA.md)). Мы восстанавливаем их ML-моделью для всего каталога и проверяем точность на ручной выборке.
3. **Честное сравнение.** Кнопка «Сравнить с бейзлайном» показывает рядом подборку по совпадению темы. Офлайн-оценка — на трёх независимых проверках, включая редакторские подборки самой платформы.
4. **Работает без сведений.** Без профиля — полезный стартовый набор и «план на неделю» из коротких материалов; при размытом запросе — уточнение в один клик, а не пустой экран.

Не входит в обязательный объём: Telegram, авторизация, реальная интеграция с платформой и оплатой, онлайн-обучение моделей, обязательные внешние LLM API, публичный хостинг (он — улучшение E03).

## 2. Принятые решения

| Решение | Выбор | Почему |
|---|---|---|
| Язык и стек | Python 3.12, FastAPI + Uvicorn, Pydantic v2, pandas/pyarrow, numpy, scikit-learn, sentence-transformers (CPU), Jinja2 + чистый JS | Один язык для ML и сервиса; FastAPI даёт Swagger для проверки API бесплатно; страница без сборки фронтенда |
| Хранилище | Без СУБД. Каталог и признаки — файлы Parquet/NumPy в `artifacts/`, события сессии — в памяти с сохранением в JSON в томе | PostgreSQL не нужен: дамп читается `pgdumplib`. Меньше сервисов — меньше причин не запуститься |
| Запуск | Один сервис в `compose.yaml`, порт 8000 | Требование кейса и наш главный приоритет — простой запуск |
| Данные в рантайме | Сервис читает только готовые `artifacts/` из репозитория. Дамп нужен лишь для пересборки артефактов | Жюри не нужно ничего никуда класть. Сам дамп не коммитим |
| Платное содержание | В артефакты не попадают тексты уроков и платных материалов. Для платного — только публичное описание лендинга и ссылка | Ограничение 06 кейса соблюдается на уровне данных, а не только интерфейса |
| LLM | Не обязательна. Объяснения строятся из причин ранжирования по шаблонам. Локальная LLM используется только офлайн у ML-инженера для разметки каталога | Нет ключей — нет проблем с запуском и с ограничением 07 |
| Кодировщик запросов | Компактная модель эмбеддингов с запуском на CPU, веса загружаются в образ при сборке. Резервный режим — TF-IDF, если модель недоступна | Запуск не должен зависеть от сети после сборки |
| Зависимости | `requirements.txt` с точными версиями для сервиса; `requirements-ml.txt` для офлайн-обучения на GPU (в образ не входит) | Требование кейса о зафиксированных версиях; образ не тянет CUDA |

Проверка сборки Docker на ранней стадии обязательна: у одного из участников Docker не установлен, поставить Docker Desktop до субботы.

## 3. Пользовательский путь и демонстрация

Страница состоит из панели профиля слева и результатов справа.

1. **Первый вход.** Сразу показан стартовый набор (без вопросов). Над ним — встроенная, не всплывающая карточка «Подберём точнее за 3 вопроса» с кнопкой «Пропустить».
2. **Онбординг, все поля необязательны:** «На каком вы этапе?» (думаю открыть / только открыл / веду бизнес / расширяюсь), «Сфера» (чипы), «Что нужно сейчас?» (чипы задач), опыт, сколько времени есть (5 минут / час / готов к курсу). Поле «Опишите задачу своими словами» — свободный текст.
3. **Результат:**
   - «Ваш маршрут» — 3–5 пронумерованных шагов и одна строка, почему такой порядок;
   - «Ещё по теме» — до 10 карточек;
   - «Быстро, за 5 минут» — короткие форматы для возврата на платформу.
4. **Карточка материала:** тип и формат, длительность, «бесплатно» / «по подписке Курс+» / цена, название, одно предложение пользы, блок «Почему вам» из 2–3 причин, кнопка следующего шага («Читать», «Скачать шаблон», «Посчитать», «Начать курс», «Оформить Курс+»), кнопки «Уже знаю» и «Не то».
5. **Обратная связь меняет выдачу сразу:** «Уже знаю» убирает материал и сдвигает уровень, «Не то» понижает похожие. Клик и отметка «прочитано» пишутся в журнал событий.
6. **Мало данных или нет совпадения:** карточка уточнения «Уточните, что ближе» с 2–4 вариантами и подборка по более общей теме.
7. **Демо-персоны:** переключатель готовых профилей, в том числе с историей. Переключатель «Сравнить с бейзлайном» — две колонки рядом.

Сценарий демонстрации (до 5 минут, закрывает приложение 2 кейса):

| Шаг | Что показываем | Что доказываем |
|---|---|---|
| 1 | Новый пользователь без данных | Холодный старт, план на неделю, частота возвратов |
| 2 | Выбирает задачу «Продвижение» и сферу «Услуги» | Маршрут с объяснением порядка |
| 3 | Включает сравнение с бейзлайном | Бейзлайн выдаёт налоговые статьи с тегом «Развитие бизнеса», мы — маршрут по продвижению для сферы услуг |
| 4 | Персона «ИП на маркетплейсах» с историей: прошёл курс по маркетплейсам | Пройденное исключено, рекомендации идут дальше по уровню; появляется уместный платный курс «УСН на маркетплейсах» с пользой без раскрытия содержания |
| 5 | Запрос «открыть автосервис в Казахстане» | Честное уточнение и общая подборка вместо выдуманного совпадения |
| 6 | Слайд с метриками | nDCG и другие метрики против бейзлайна, вклад компонентов |

## 5. Контракты

### 5.1 Материал (строка `catalog.parquet`)

| Поле | Тип | Источник |
|---|---|---|
| `item_id` | str | `Id` исходной таблицы |
| `item_type` | article / document / course / webinar / podcast / glossary / calculator | таблица |
| `format` | quick_answer / guide / template / tool / course / recording / podcast | правила: глоссарий и статьи до 5 минут — quick_answer; документ — template; калькулятор — tool |
| `title`, `summary` | str | `Title`; `Description` без HTML, до 300 символов |
| `duration_min` | int или null | разбор `Duration` («2,5 часа» → 150) |
| `access` | free / subscription / paid | `Courses.Cost` (`NULL` — бесплатно), `CourseTypes`, `CourseSubscriptions`, `IsPublic` / `IsClosed` |
| `price_rub` | int или null | `Courses.Cost`, тариф «Курс+» |
| `url` | str | `PLATFORM_BASE_URL` + путь по типу + `Url`-слаг из дампа |
| `topics`, `raw_tags`, `raw_industries`, `subject` | list[str] / str | `ContentSettings*`, `ArticleSubjects`, `DocumentTypes` после нормализации |
| `published_at` | datetime | `Published` или `StartsAt` |
| `popularity`, `completion_rate`, `rating` | float или null | `CourseUserBindings`, `UserRatings` (только курсы и калькуляторы) |
| `index_text` | str | Текст для эмбеддинга: заголовок, описание, подзаголовки, начало тела для бесплатных материалов. Для платных — только публичный лендинг. В git не хранится, лежит в `data/processed/` |

Включаем только опубликованные и неудалённые материалы. Уроки отдельно не рекомендуются: они часть курса.

### 5.2 ML-разметка (`item_labels.parquet`)

| Поле | Значения |
|---|---|
| `stages` | idea / launch / operating / growth (несколько) |
| `level` | beginner / intermediate / advanced |
| `tasks` | 1–3 задачи из таксономии (раздел 5.4) |
| `industries` | сферы из таксономии или пусто — «для всех» |
| `label_source` | rule / model / llm — для отладки и объяснений |

### 5.3 Профиль, событие, ответ

```text
Profile:        stage?, industries[]?, tasks[]?, experience?, time_budget?, free_text?
Event:          user_id, item_id, type (view|complete|save|enroll|rate|known|dislike), value?, ts
Recommendation: item, score, reasons[{code, weight, params}], next_step{kind, label, url}
Response:       route[], more[], quick[], clarification?{question, options[]}, mode (ours|baseline), profile_used
```

Любое поле профиля может отсутствовать. Коды причин фиксированы списком (например `task_match`, `stage_fit`, `beginner_friendly`, `industry_match`, `continues_history`, `popular_with_similar`, `short_format`, `fresh`, `next_level`, `deep_dive_course`). Ранжирование отдаёт коды и параметры, тексты собирает `explain.py`.

### 5.4 Таксономия профиля

Стадии: думаю открыть; только открыл (до года); веду бизнес; расширяюсь.

Задачи (около 14, связываются с `Topics`, `Tags`, `ArticleSubjects`): открыть и зарегистрировать бизнес; выбрать налоговый режим; налоги и отчётность; учёт, деньги и платежи; 115-ФЗ и банковские ограничения; продвижение и маркетинг; продажи и клиенты; маркетплейсы и онлайн-продажи; команда и найм; договоры и юридические вопросы; финансы и финансирование; ИИ и автоматизация; ВЭД и бизнес за рубежом; франчайзинг.

Сферы — нормализованные `Industries` без витринных меток: ECom, розница, услуги, HoReCa, B2B, B2G, производство, строительство и недвижимость, транспорт и логистика, оптовая торговля, финансы и страхование.

Для каждой задачи и стадии хранится короткое описание на понятном языке — оно же текст для эмбеддинга при сопоставлении свободного запроса.

## 6. Алгоритм рекомендаций

### 6.1 Восстановление разметки каталога (офлайн, GPU)

1. Правила с высокой точностью: `Industries` «Без опыта» → beginner; рубрика «ИП», «Самозанятость», тег «Старт бизнеса» → launch; документы «Старт и закрытие бизнеса» → launch и т. п.
2. Модель по эмбеддингам: классификаторы (логистическая регрессия или kNN) для задач и сфер, обученные на уже размеченной части каталога.
3. Локальная LLM на GPU (класса 7–8B, Instruct, ответ строго в JSON) для стадии и уровня, где правил и разметки нет. Данные не покидают машину команды.
4. Контроль: 120 материалов размечаются вручную вторым участником вслепую; считаются точность и macro-F1 по каждому полю. Источник с худшим качеством на поле не используется. Результат — таблица в отчёте.

### 6.2 Эмбеддинги и выбор модели

Кандидаты: TF-IDF (базовая точка), `cointegrated/rubert-tiny2`, `intfloat/multilingual-e5-small`, `deepvk/USER-base`, `intfloat/multilingual-e5-base`. Критерии выбора: Recall@10 и nDCG@10 на редакторских подборках `RecommendedItems` + `DocumentBindings`, время кодирования запроса на CPU (цель — до 150 мс), размер весов (цель — до 500 МБ). Длинные статьи кодируются по фрагментам с усреднением. Дообучение модели — улучшение E05, только при выигрыше на отложенной части разметки.

### 6.3 Конвейер ранжирования

1. **Понимание профиля.** Свободный текст кодируется и сопоставляется с описаниями задач, стадий и сфер; найденное с уверенностью выше порога дополняет профиль и помечается как «понято из текста». Пустые поля профиля могут достраиваться по истории.
2. **Кандидаты (200–300):** семантическая близость к профилю; совпадение задачи и темы; соседи материалов из истории (эмбеддинги + граф совместных записей на курсы); популярные и хорошо проходимые курсы для холодного старта.
3. **Скоринг** — взвешенная сумма признаков из диапазона [0, 1]:

| Признак | Смысл |
|---|---|
| `f_semantic` | Косинусная близость эмбеддингов профиля и материала |
| `f_task` | Совпадение задач профиля и разметки материала |
| `f_stage` | Матрица совместимости стадий: «думаю открыть» → материалы launch подходят на 1.0, growth — на 0.2 |
| `f_level` | Соответствие уровня опыту; продвинутое для новичка штрафуется |
| `f_industry` | 1 — та же сфера, 0.6 — материал для всех, 0 — чужая сфера |
| `f_format` | Соответствие бюджету времени: 5 минут → quick_answer / tool, курс → course |
| `f_history` | Близость к положительным событиям истории; отрицательные события снижают похожие |
| `f_quality` | Сглаженные доля завершений курса и средняя оценка |
| `f_popularity` | Логарифм популярности, нормированный; вес растёт при пустом профиле |
| `f_fresh` | Свежесть публикации, для тем про изменения законов |
| `f_offer` | Подписка или платный курс уместны: задача требует системного обучения или пользователь уже прошёл бесплатное по теме |

   Начальные веса задаются вручную, затем подбираются поиском по сетке на 60% тестовых профилей; метрики публикуются по оставшимся 40%. Линейная модель выбрана ради объяснимости: вклад признака и есть причина в карточке. Learning-to-rank — улучшение E02.
4. **Переранжирование:** MMR по эмбеддингам для разнообразия; не больше двух материалов одной узкой темы в топ-5; минимум два разных формата в топ-5; не больше одного платного материала в топ-5; исключены пройденные и отмеченные «Уже знаю».
5. **Маршрут:** из топа выбираются 3–5 материалов по ролям «понять» (quick_answer, guide уровня ниже), «сделать» (template, tool), «углубиться» (course, recording) и упорядочиваются по уровню. Если для роли нет подходящего материала, шаг пропускается, а не заполняется нерелевантным.
6. **Уверенность и уточнение:** если лучшая семантическая близость ниже порога либо профиль пуст и свободный текст многозначен, ответ содержит `clarification` с 2–4 вариантами — главными кластерами задач среди кандидатов — и подборку по более общей теме. Порог подбирается на профилях «нет совпадения».

### 6.4 История

Веса событий: complete 1.0, enroll 0.7, save 0.6, view 0.4, rate ≥ 4 +0.3, rate ≤ 2 и dislike −0.7, known — исключить материал и повысить уровень по теме. Профиль-вектор истории — взвешенное среднее эмбеддингов с затуханием по времени. Курс в процессе прохождения поднимается карточкой «Продолжить курс» с номером следующего урока — главный механизм возврата на платформу. Для курсов дополнительно используется граф совместных записей из `CourseUserBindings`.

Демо-история: реальные обезличенные пользователи с несколькими курсами плюс синтетические события просмотров статей и документов, сгенерированные по персонам (генератор фиксирован зерном и лежит в `pipeline/`).

### 6.5 Холодный старт и частота возвратов

- Пустой профиль: стартовый набор из 6–8 материалов — популярный курс для начинающих с высокой долей завершений, калькулятор выбора налогового режима, востребованный шаблон, 2–3 статьи по самым частым темам, свежий материал про изменения законов. Набор разнообразен по форматам.
- «План на неделю»: 5 коротких материалов до 10 минут по одной теме с порядком по дням — мотивация вернуться завтра. Без уведомлений и поп-апов.
- Блок «Быстро, за 5 минут» в каждой выдаче.

### 6.6 Бейзлайн

Подборка по совпадению темы: задача профиля → темы `Topics`; материалы с этой темой сортируются по популярности, затем по дате. Без стадии, уровня, сферы, истории и разнообразия. При пустом профиле — самые популярные материалы. Бейзлайн реализован в том же API (`mode=baseline`) — сравнение видно в интерфейсе и считается тем же кодом оценки.

## 7. Объяснения и следующий шаг

Каждая карточка — 2–3 причины из кодов с наибольшим вкладом, человеческим языком и с конкретикой профиля: «Подходит под вашу задачу „продвижение“ и сферу „услуги“», «Для тех, кто только начинает», «Займёт 8 минут», «Продолжает курс „Маркетплейсы: с чего начать“, который вы прошли». Над маршрутом — одна строка о порядке: «Сначала разберёмся в терминах, затем подготовим документы, после — системный курс».

Следующий шаг зависит от формата и доступа: читать, скачать шаблон, посчитать в калькуляторе, начать курс, посмотреть запись, оформить «Курс+».

Платные и подписочные материалы: показываются только название, публичное описание пользы (лендинг: «Кому подойдёт», «Что вы получите») и ссылка на страницу материала или покупки, собранная из слага дампа. Тексты уроков, их структура и содержание не выводятся. Автотест проверяет, что ответ API для платного материала не содержит текста из `LessonEmbedItems`.

Запрещено обещать результат («увеличит продажи на 30%») и придумывать факты о материале: объяснение собирается только из данных и разметки.

## 8. API

| Метод | Назначение |
|---|---|
| `GET /api/health` | Готовность: загружены ли артефакты, режим кодировщика (модель или резервный TF-IDF) |
| `GET /api/meta` | Таксономии для онбординга |
| `GET /api/personas` | Демо-персоны с профилями и историей |
| `POST /api/recommendations` | Профиль, `user_id` (необязателен), `mode`, `limit` → маршрут, подборки, уточнение, причины, следующий шаг |
| `POST /api/events` | Запись события; следующий запрос учитывает его |
| `GET /api/items/{item_id}` | Карточка материала без платного содержания |

| `GET /docs` | Swagger |

Нефункциональные требования: ответ рекомендаций до 1 секунды на ноутбуке без GPU; холодный старт контейнера до 30 секунд; одинаковый вход даёт одинаковый ответ; ошибки возвращаются понятным сообщением, а не трассировкой.

## 9. Офлайн-оценка

Три независимые проверки; всё считает одна команда `python -m alfarec.eval`, результат — `reports/eval.md`.

1. **Тестовые профили (главная).** 36 профилей: три типа аудитории из кейса × стадии × сферы × задачи. Из них 8 с историей, 6 с минимумом сведений (только свободный текст или ничего), 4 «нет совпадения». Оценки релевантности: пул из топ-10 бейзлайна и нашей системы с вариантами, перемешанный без указания источника, разметка 0/1/2 по инструкции. Оба участника размечают по половине профилей, 5 профилей — оба, для согласованности (каппа Коэна). Метрики: nDCG@10, Precision@5, MRR, доля материалов подходящей стадии и уровня в топ-5, число форматов в топ-5, внутрисписковое разнообразие, покрытие каталога, доля профилей «нет совпадения» с выданным уточнением.
2. **Редакторские подборки.** `RecommendedItems` и `DocumentBindings`: по исходному материалу предсказать связанные; Recall@10, nDCG@10. Проверяет текстовую близость и выбор модели эмбеддингов.
3. **Следующий курс по поведению.** 1562 пользователя с двумя курсами и больше: последний по дате курс скрывается, HitRate@5 и MRR против популярности.

Абляции: убираем по очереди разметку стадии и уровня, историю, переранжирование — показывает вклад каждой части. Метрики сообщаются как есть, включая проигрыши. До измерений проценты не обещаем.

## 10. План проверки влияния на конверсию после внедрения

Подробный план — [docs/ab-test.md](../ab-test.md) (карточка B11). Кратко:

- Дизайн: A/B по пользователю, рандомизация по хешу идентификатора, 50/50. Контроль — текущая выдача или подборка по теме, тест — наша система. Перед запуском — A/A-проверка сплита.
- Главная метрика: доля пользователей, оплативших платный курс или подписку «Курс+» за 28 дней после назначения в группу — первого запроса страницы рекомендаций, до вызова алгоритма. Так в анализ входят и пользователи, которым выдача не отрисовалась.
- Вторичные: CTR рекомендаций, записи на курсы, доля завершённых, **активные дни на пользователя за 28 дней** (продуктовая цель кейса), возврат на 7-й и 28-й день.
- Ограничители: доля отказов со страницы рекомендаций, жалобы и «Не то», отписки, доля платных материалов в выдаче.
- Расчёт объёма выборки по формуле для долей с примером и чувствительностью к базовой конверсии. Пример: при базовой конверсии 1% и относительном эффекте +20% нужно около 43 тыс. пользователей на группу при α = 0.05 и мощности 80%. Длительность — не меньше двух полных недель; CUPED по активности до теста для снижения дисперсии.
- Логирование: показ с позицией, кодами причин и версией модели; клик; запись; покупка. Без этого эффект не атрибутировать.
- Этапы: офлайн-оценка → interleaving-тест для быстрой проверки ранжирования → A/B на 10% трафика → раскатка.

## 12. Правила кода

- Код, идентификаторы и сообщения коммитов — на английском; README и документация — на русском.
- Форматирование и линтер — `ruff format` и `ruff check`; тесты — `pytest`. Всё запускается в CI вместе с первым кодом.
- Комментарии только там, где решение неочевидно: почему так, а не что делает строка. Без пересказа кода, без эмодзи, без декоративных разделителей.
- Небольшие осмысленные коммиты в формате Conventional Commits; каждая карточка — своя ветка и PR.
- Ноутбуки — только локально; в репозиторий идут скрипты, воспроизводящие результат.
- Случайность фиксируется зерном; артефакты пересобираются командой из README.

## 14. Приёмка обязательного ядра

| Сценарий | Критерий прохождения |
|---|---|
| A01. Чистый запуск | На второй машине: свежий клон → `docker compose up --build` → страница открывается, `/api/health` в порядке, без ручных шагов |
| A02. Новый пользователь с задачей | «Продвижение» → маршрут из 3–5 шагов разных форматов с объяснением порядка, все материалы по теме |
| A03. История | Персона с историей: пройденное исключено, есть причина «продолжает…», выдача отличается от той же персоны без истории |
| A04. Холодный старт | Пустой профиль → стартовый набор и «план на неделю» разных форматов, без ошибок |
| A05. Мало данных / нет совпадения | Запрос вне каталога → уточнение с вариантами и общая подборка; нет выдуманных совпадений |
| A06. Объяснения и шаг | У каждой карточки 2–3 причины, основанные на данных, и кнопка следующего шага с рабочей ссылкой |
| A07. Платное содержание | Платный и подписочный материал: только польза и ссылка; автотест на отсутствие текстов уроков проходит |
| A08. Сравнение с бейзлайном | `reports/eval.md` воспроизводится командой; переключатель в интерфейсе работает |
| A09. Онбординг необязателен | Любой вопрос можно пропустить; выдача обновляется после каждого ответа |
| A10. Сдаваемый комплект | README, Dockerfile, compose.yaml, .dockerignore, requirements.txt, .env.example, PDF; доступ жюри открыт; дамп не в репозитории |

## 15. Риски

| Риск | Что делаем |
|---|---|
| Docker нет на одной из машин | Установить в субботу утром; ранняя сборка образа в субботу вечером |
