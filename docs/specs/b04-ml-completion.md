# B04: завершение ML-конвейера

Продолжение [B04](../tasks/CORE.md) по разделам 6.1–6.2 [ТЗ](2026-11-13-recommender-tz.md). Владелец GPU подтвердил запуск на текущей машине: RTX 4070, 12 ГБ. Входы B02 переданы в локальную `data/handoff/`, закрытые тексты не коммитятся и не отправляются внешним API.

## Решение и варианты

Сравниваем TF-IDF и все четыре кодировщика ТЗ: rubert-tiny2, multilingual-e5-small, USER-base, multilingual-e5-base. Фиксируем ревизии весов. Длинные тексты делим по токенам с усреднением нормированных векторов; E5 использует префиксы query/passage. Один исходный материал целиком относится к tune либо holdout редакторских связей. Выбор по nDCG@10 на tune при CPU p95 менее 150 мс; holdout публикуется отдельно после выбора. Размер и скорость показываем даже для проигравших вариантов. Повторно используем существующие поведенческие переходы.

Метки: сохраняем правила с явным происхождением; классификаторы задач и сфер обучаем на исходных редакторских полях, без ручных 120 оценок; локальная Qwen2.5-7B-Instruct в 4 битах восстанавливает стадии и уровень по публичным карточкам, выдаёт проверяемый JSON. Невалидный ответ не становится меткой. Ручные 120 материалов служат контролем, а не обучением. Сравниваем поля и источники, слабые источники отключаем, решение и ограничения сохраняем. Этот контроль после выбора источников не называется независимым итоговым тестом.

Граф: отдельные матрицы семантических соседей и совместных записей, общий порядок ID, происхождение и хеши. Скрытые редакторские связи не используются для построения графа. Поведенческий граф полного snapshot не используется в оценке следующего курса со скрытой записью.

CPU-сервис загружает локальный безопасный формат весов и проверяет каталог, ID, размерности, конечность и хеши артефактов. Отсутствующие необязательные веса дают явный TF-IDF; повреждённые артефакты считаются ошибкой. Настройка ENCODER: auto/tfidf/dense. Health сообщает фактический режим. Существующие API-схемы сохраняются. ML-метки и граф подключаются к ранкеру через внутренние интерфейсы; веса B06 не подбираются в этой задаче.

## Поставка и ограничения

Уточнения независимого ревью: backend LLM — Transformers + bitsandbytes NF4 на CUDA; до полного прогона обязательна проба загрузки и JSON, замер VRAM. Между моделями процесс завершается. Seed labels задач — только точные tags/subjects из таксономии, не широкие Topics; сферы — точные raw_values. При нехватке обучающих примеров классификатор воздерживается. Источник хранится отдельно для tasks/industries/stages/level. Контроль отклоняет неполные или дублирующиеся ID, включая все 120 ручных материалов. CPU-замер: фиксированные короткие и длинные запросы, 4 потока, 5 warmup, 30 измерений, p50/p95 и CPU; полная рекомендация измеряется отдельно. Цель веса — до 500 МБ. Если ни одна модель не проходит скорость, полного закрытия нет: требуется оптимизация или отдельное согласование изменения объёма.

Большие веса не помещаем в обычные Git-коммиты. Docker получает модель по зафиксированной ревизии на этапе сборки; после сборки запуск без сети. В репозитории — компактные производные артефакты, контрольные суммы и отчёты без полных текстов. Внешние API генерации и платные сервисы не используются. Неудачная загрузка модели или качество ниже базовой точки отражаются явно, без выдуманных результатов.

## Приёмка

- Воспроизводимая команда GPU-подготовки и таблица всех кандидатов с Recall@10/nDCG@10, CPU p50/p95, размером и ревизией.
- Векторы float16, ML-метки с источником, граф и манифесты согласованы с каталогом 1497 материалов.
- Отчёт по реальным ручным 120 меткам: accuracy и macro-F1 по полям и источникам; исходные ответы сохранены.
- Тесты повреждений и несовместимости, реальный dense CPU-запрос и явный резерв без весов.
- Проверки проекта и независимое ревью; CPU Docker с моделью работает без сети, A02–A05 сохраняются.
- B04 получает done только после принятого PR; merge требует отдельного разрешения пользователя.
