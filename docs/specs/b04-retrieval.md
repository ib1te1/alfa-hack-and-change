# B04: индекс извлечения кандидатов

Первый этап [B04](../tasks/CORE.md), исполнитель `prolgrammer`, ветка `feature/b04-retrieval-index`. Основа — каталог B02, PR #7. API, интерфейс, каталог и его публичный контракт остаются в границах своих задач.

## Решение

Индекс строится офлайн и загружается из файлов без pickle, ключей и сетевых обращений. TF-IDF служит обязательным резервом; его косинусная близость является лексическим сигналом, а не доказательством семантического качества. Символьные n-граммы 3–5 позволяют учитывать русские словоформы без внешней морфологической модели. Отдельный интерфейс векторного кодировщика позволяет подключить выбранную нейросетевую модель после сравнения на редакторских связях.

Источник по умолчанию — согласованный `index_text.parquet`. Режим `metadata` включается явно и использует только название и краткое публичное описание каталога. При отсутствии полных разрешённых текстов нельзя молча подменять источник. В манифесте сохраняются источник текста, хеши входов, упорядоченные ID, параметры и версии библиотек.

В рантайме запрос кодируется тем же преобразованием, что и материалы, а результат содержит ID и конечный score. Пустой запрос и запрос без известных n-грамм возвращают пустой список. Исключения из истории применяются по ID. Равные оценки упорядочиваются стабильно. Поиск выдаёт кандидатов; стадия, уровень, история и маршрут ранжируются отдельно в B05.

Повреждённые, устаревшие и несовместимые артефакты не должны подменяться случайной выдачей. Недоступный нейросетевой кодировщик допускает явный переход на TF-IDF с указанием фактического режима. Несовпадение набора материалов считается ошибкой данных.

## Границы этапа

В репозитории уже есть метаданные 1497 материалов, но нет исходного индекса текстов, редакторских связей и журнала записей. На этом этапе можно проверить сборку, загрузку, воспроизводимость, выбор кандидатов и скорость. Нельзя объявлять выбранную модель лучшей, генерировать фиктивные метрики релевантности или утверждать точность меток стадии/уровня.

Эмбеддинги, ML-метки и граф совместных записей остаются в B04 после передачи входных данных. Ручная оценка 120 материалов не заменяется автоматической разметкой. Приёмка всей B04 не закрывается одним готовым индексом TF-IDF.

## Проверка

- Сборка и чтение индекса на реальном каталоге с явным режимом metadata.
- Точные ID и хеши источников, отсутствие произвольной десериализации кода.
- Поведенческие тесты поиска, пустого ввода, исключений, устойчивого порядка и повреждённых файлов.
- Воспроизводимый замер времени кодирования/поиска на CPU; отдельно от оценки релевантности.
- Независимое ревью, тесты и CI. Слияние выполняется отдельно.
