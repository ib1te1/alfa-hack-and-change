# B05: применение выбранных весов в сервисе

Продолжение согласованного ранжирования: B04 уже подключает dense-поиск,
метки и семантический граф. Не меняем публичные контракты рекомендаций.

## Решение

`load_ranker` и API автоматически читают `artifacts/weights.json`; локальный
путь можно переопределить через `WEIGHTS_PATH`. Отсутствие стандартного файла
означает начальные веса. Явно указанный отсутствующий файл, повреждённый JSON,
неизвестные признаки, отрицательные/бесконечные значения и несовместимый каталог
отклоняются. API сохраняет доступность через бейзлайн с `degraded`.

Файл версии 1 содержит полный словарь `weights`, `catalog_sha256` и `provenance`
с протоколом выбора. Программные частичные overrides нужны для абляций и
подбора; они проверяются и накладываются на текущие рабочие веса. Для отдельного
сравнения с начальными весами подбор явно отключает загрузку файла.

Файл читается при старте, без скрытого обновления между запросами. Эффективные
веса доступны офлайн-оценке; исходные веса не выдаются за подобранные.

## Приёмка

- HTTP-запросы используют сохранённые веса, контрольные веса меняют score.
- Ошибочный файл приводит к явному резерву, без NaN в ответах.
- Dense и TF-IDF сохраняют историю, квоты, отсутствие дублей, холодный старт,
  маршруты и уточнение; задержка ответа на CPU меньше секунды.
- Подбор и доказательства релевантности относятся к отдельной B06.
- До появления принятых весов B06 полная B05 остаётся в review.
