# B08: достоверность и устойчивость объяснений

Продолжение [B08](../tasks/CORE.md) в пределах принятого раздела 7
[ТЗ](2026-11-13-recommender-tz.md). Основа объяснений уже слита в PR #11;
ранжирование и интеграция развиваются отдельно в PR #20 и #21.

## Проблема

Общая популярность материала не доказывает популярность у людей с похожими задачами.
Положительное действие в истории не доказывает, что человек изучил материал.
Заголовок длиной 200 символов допустим в каталоге, но вместе с фразой объяснения
может превысить ограничение `Reason.text` и нарушить контракт ответа API.

## Объём исправления

- Формулировать популярность без утверждений о недоступных когортах.
- Описывать связь с историей без предположений о завершении материала.
- Ограничивать длину текста с сохранением смысла, включая длинные заголовки.
- Проверить все форматы и доступы: следующий шаг ведёт на исходную страницу;
  существующая кнопка продолжения курса сохраняется.
- Проверить сериализацию карточек и ответы API на допустимых граничных данных.

Коды причин, поля контрактов, ранжирование, веса и исходный каталог не меняются.
Приёмка всей B08 после интеграции B05 остаётся отдельным этапом; отсутствие
исходного дампа не позволяет объявить проверку текстов уроков пройденной.

## Приёмка

Тексты не приписывают пользователю отсутствующие действия или принадлежность к
когорте. Все объяснённые карточки повторно проходят валидацию Pydantic и API
на заголовках предельной длины. Локальные проверки совпадают с CI;
совместимость с PR #21 проверяется отдельно от основной ветки.

При интеграции с автоприёмкой B13 результат A07 подтверждается только фактически
выполненными проверками публичных полей и текстов уроков. Пропущенный тест не
означает прохождения сценария; код возврата pytest сам по себе недостаточен.
