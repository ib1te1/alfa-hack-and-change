их происхождение подтверждено участником команды. Они относятся к пакету

Совпадают все пять статусов; в одной паре оба участника выбрали
`unjudgeable`. Это ещё не завершённый разбор инструкции.

**Что делать:**

   Они уже собраны в [архиве калибровки](../../reports/calibration/README.md).
   Исходные JSON не редактировать и не заменять их хеш на текущий.
2. Два участника разбирают прежде всего `unjudgeable`, записывают окончательный
   статус каждой пары, основание и решение: требуется ли уточнение инструкции.
   Совпадение ответов не заменяет этот шаг.
3. Зафиксировать, к какой версии относится приёмка. Первые четыре показанные

   «Госзакупки: теория и практика» на глоссарий «Тендер» для отделения от B06.
   Чтобы принять именно текущий пакет штатной командой, участники заполняют
   текущую форму независимо и выполняется `calibration compare` по
   [инструкции](../calibration.md). Старые оценки остаются историческим результатом.
4. Если меняется инструкция, до основной разметки пересобрать текущий пакет B03
   и пул B06. Не переносить старые оценки на новые карточки автоматически.
5. Указать дату, коды A/B, принятый пакет, исходные ответы и итог обсуждения в B03.

**Можно закрыть, когда:** есть валидные независимые ответы принятой версии,
человеческий разбор всех пяти пар и решение по инструкции. Новая модель и GPU

## B04: закончить ML-подготовку

**Состояние:** `blocked` для полного объёма. Работает TF-IDF по метаданным;
есть интерфейс `DenseIndex`, но загрузка конкретной модели, её веса, векторы
и ML-метки ещё не реализованы. Поведенческие переходы курсов уже есть в
`artifacts/course_transitions.json`: заново делать эту часть не нужно.

**Вход:** исполнитель B02 `enioZz95` передаёт Гланде и исполнителю CPU-интеграции
папку `data/handoff/` с текстами, редакторскими связями, записями на курсы и
манифестом. В этой среде исходных файлов нет. Нужны файлы версии из
[отчёта B02](../../reports/b02_handoff.md), либо исходный дамп для их получения.
Проверить хеши, покрытие ID, доступ и происхождение текстов. Передача — вне Git.

**Что делать:**

1. **Гланда, GPU:** сравнить кандидатов из ТЗ с TF-IDF на одной редакторской
   выборке: Recall@10, nDCG@10, размер весов. Проверку скорости каждого
   подходящего кандидата проводить на CPU. Зафиксировать точную ревизию модели.
2. **Гланда, GPU:** посчитать векторы каталога в согласованном порядке ID;
   подготовить метки стадии, уровня и задач с источником каждой метки.
   Внешним сервисам закрытые материалы не передавать.
3. **Независимый участник, без GPU:** разметить 120 материалов через
   `artifacts/label_check/form.html`. Выборка и форма уже готовы. Скачать JSON
   и выполнить `python -m alfarec.eval.label_check score <ответ.json>`.
   До появления ML-меток команда сравнивает правила; это не оценка будущей модели.
4. **Гланда:** посчитать качество меток по полям и источникам, отключить слабые
   источники. Дополнить поведенческие связи соседями по эмбеддингам, отделив
   данные настройки от отложенной оценки; сохранить граф и происхождение рёбер.
5. **CPU-интеграция:** реализовать загрузку модели и плотного индекса, проверку
   версии/ID, явный резерв TF-IDF. Сейчас `load_ranker()` загружает именно
   `TfidfIndex` по метаданным — одного появления `.npy` недостаточно.

**Выход:** `item_vectors.npy`, упорядоченные ID, `item_labels.parquet`,
согласованный граф `item_graph.npz`, веса и ревизия модели, отчёт сравнения
моделей и отчёт ручной проверки меток.

**Можно закрыть, когда:** выбранная модель работает в CPU-сервисе,
кодирование запроса быстрее 150 мс, образ содержит веса и работает без сети,
при недоступных весах явно включается TF-IDF, качество меток подтверждено
человеком. Если объём сокращается, сначала явно изменить принятую спецификацию;
текущий TF-IDF сам по себе не закрывает всю B04.
