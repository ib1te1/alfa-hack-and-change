Отчёт создаёт `python -m alfarec.eval` по каталогу, индексу B04, ранжированию B05 и входам из `data/handoff/` (см. [отчёт передачи](b02_handoff.md)). Это проверки без ручной разметки. Главная метрика ТЗ — nDCG@10 на тестовых профилях по оценкам 0/1/2 — ещё не посчитана: нужны оценки двух участников. Веса ранжирования ручные, абляций нет.

## Следующий курс по поведению

Пользователи стабильно делятся по хешу псевдонима: 60% (`tune`) строят переходы «курс → следующий курс» и подбирают их вес, на остальных 40% (`holdout`) считается таблица. Случаев в `holdout` с однозначным последним курсом: 191. Последний по дате курс скрыт. Прогноз строится на начало месяца его записи. История содержит enroll по дате записи и complete по фактической дате завершения только из более ранних месяцев. При неизвестной дате завершения complete не создаётся. Неоднозначный последний месяц, неизвестные даты записей и повторный целевой курс исключены.

| Метод | HitRate@5 | MRR |
|---|---|---|
| Наша система с переходами между курсами | 0.738 | 0.573 |
| Наша система без переходов (только содержание) | 0.105 | 0.161 |
| Популярность | 0.770 | 0.271 |

Это snapshot-диагностика с историей as-of, а не полный временной backtest. Популярность, качество и доступность материалов взяты из полного снимка каталога, включая период после прогноза. Величина влияния этой утечки агрегатов неизвестна; для временной оценки нужны исторические снимки всех признаков.

Курсы из выдачи идут первыми, недостающие места дополняются по популярности. Переходы и их априорная популярность считаются только по записям `tune`, поэтому скрытые курсы `holdout` в этот признак не попадают. Вес, смесь и сглаживание выбирает `python -m alfarec.eval.tune_sequence` внутри `tune` ([протокол](sequence_tuning.md)); на `holdout` ничего не подбиралось. Признак популярности ранжирования и строка «Популярность» по-прежнему используют полный снимок каталога.

## Релевантность по ручной разметке

Пул выдач для разметки готов (`python -m alfarec.eval.judgments pool`, форма — `artifacts/judgments/form.html`), оценок двух участников ещё нет. nDCG@10, Precision@5 и MRR нашей системы и бейзлайна появятся здесь после `python -m alfarec.eval.judgments merge`. Веса, кроме переходов между курсами, не подбирались.

В пул для разметки входят только наша система и бейзлайн (решение команды по объёму ручной работы). Абляции не измерены: без стадии и уровня, без истории, без переранжирования. Их списки сохраняются, но метрики по частично оценённому пулу были бы смещены.
