# Офлайн-оценка: этап 1

Отчёт создаёт `python -m alfarec.eval` по каталогу, индексу B04, ранжированию B05 и входам из `data/handoff/` (см. [отчёт передачи](b02_handoff.md)). Это проверки без ручной разметки. Главная метрика ТЗ — nDCG@10 на тестовых профилях по оценкам 0/1/2 — ещё не посчитана: нужны оценки двух участников. Веса ранжирования ручные, абляций нет.

## Следующий курс по поведению

**Метрики сняты до пересчёта.** Предыдущая версия создавала complete в дату записи по итоговому status=2, даже если курс завершался после скрытой записи. Старые HitRate@5/MRR и число случаев не подтверждают исправленный протокол.

Теперь момент прогноза — начало месяца скрытой записи. В истории остаются enroll по дате записи и complete по фактической completed_at только из строго более ранних месяцев. Неизвестная дата завершения не превращается в complete; неизвестные даты записей, неоднозначный последний месяц и повторный целевой курс исключаются. Регрессии проверяют завершение до, в том же месяце и после прогноза, а также фактически передаваемую рекомендателю историю.

Для пересчёта нужны `data/handoff/course_enrolments.parquet` и `editorial_pairs.parquet` версии из [отчёта передачи](b02_handoff.md). Эти файлы передаются вне Git и на машине исправления отсутствуют; синтетические тесты не заменяют измерение на них.

Даже после пересчёта это snapshot-диагностика с историей as-of, а не полный временной backtest: популярность, качество и доступность материалов остаются агрегатами полного снимка каталога, включая период после прогноза. Влияние утечки этих агрегатов неизвестно. Для временной оценки нужны исторические снимки всех признаков.
